换手机时导出一次通讯录，CRM 系统里再导出一份客户名单，同事和客户发来的名片又是一个 `.vcf`。几个月下来，手边躺着四五个 VCF 文件，人名互相重叠，却没有一个包含完整名单。

把它们「合并」听起来是一件事，实际是两件：先把所有联系人汇总到同一份列表里，再去掉重复——同一个人在一份文件里存的是手机号，在另一份里存的是座机，姓名写法也可能不一样。下面比较三种做法：借表格合并、在通讯录里合并、直接拼接文本文件，并说明各自要花多少手工、可能丢掉什么。

## 为什么直接拼接 VCF 不够

VCF 是一串文本块。每个联系人由 `BEGIN:VCARD` 开头、`END:VCARD` 结尾，一个文件里可以装几百条。所以把一个文件接在另一个后面，文件本身不会坏，手机也能照常导入。

问题在于它什么都不比较。同一个「张伟」出现在两份文件里，合并后还是两条，你得自己决定删哪一条。它也不管文件边界：如果前一个文件的最后一行没有换行符，拼起来就是 `END:VCARDBEGIN:VCARD` 挤在同一行，没有程序能读懂。编码也是隐患：一份 UTF-8、一份 GBK，或者 Windows 的 CRLF 混着 macOS 的 LF，中文就可能变成乱码。

## 方法一（推荐）：通过表格合并

能逐行比较的是表格。可靠的做法是先把 VCF 变成一张表、清掉重复，再重新生成一个 VCF。这一步没有「一键合并」按钮，要用两个工具、走两步。

1. 打开 [VCF 转 Excel 工具](/zh/vCard-to-Excel/)，一次选中多个 `.vcf`，或者把它们一起拖进上传区。所有文件的联系人会汇总到同一张预览表里。
2. 检查这张合并后的表：一条联系人占一行，姓名、电话、邮箱、公司、职位、地址、备注各占一列。
3. 导出 **XLSX** 或 **CSV**，用 Excel 打开，先按姓名排序，再用 `数据` → `删除重复项` 去掉重复行。
4. 把整理好的表交给 [Excel 转 VCF 工具](/zh/Excel-to-vCard/)，导出的就是一个包含全部联系人的 `.vcf`。

整个过程在浏览器本地完成，文件不会上传到服务器，客户名单、员工通讯录都能放心处理。解析器支持 vCard 2.1、3.0、4.0，一个文件里有多条联系人也能读；多个电话、多个邮箱会拆到不同列；导出 CSV 时会写入 UTF-8 BOM，用 Excel 双击打开中文也不乱码。

## 方法二：在通讯录应用里合并

如果你的目标不是文件，而是日常用的通讯录，可以把 VCF 逐个导入同一个账户，最后统一导出一个 VCF。

- **macOS 通讯录**：`文件` → `导入`，每导入一个 VCF 重复一次；最后 `文件` → `导出` → `导出 vCard`。iPhone 上则是点开收到的 `.vcf` 逐个添加，要批量导出还是用 `icloud.com` 的通讯录。
- **Google 通讯录**：打开 `contacts.google.com`，左侧菜单选「导入」，一次一个文件；最后「导出」→「vCard」。
- **Outlook**：`文件` → `打开和导出` → `导入/导出` → `从另一程序或文件导入` → `vCard 文件 (.vcf)`，每个文件走一遍向导。

缺点是慢。通讯录不会替你判断重复：Google 通讯录的「合并重复项」、iPhone 的「链接联系人」都只是给出候选，最后仍要你自己点。导入时字段还会被规范化，长备注、第二个地址、特殊属性可能被截断。

## 方法三：直接拼接文本文件

VCF 本来就是纯文本，也可以直接把文件接起来。macOS 和 Linux 在终端里：

```
cat mingpian1.vcf mingpian2.vcf > merged.vcf
```

Windows 在命令提示符里用 `copy /b`，避免按文本重新解释字节：

```
copy /b mingpian1.vcf+mingpian2.vcf merged.vcf
```

不想用命令行，就用记事本打开第一个文件，把光标移到末尾，粘贴第二个文件的内容，另存为 `.vcf`。拼接前要确认每个文件都以换行结尾，否则得手动在两个块之间补一个换行。

它很快，也不依赖任何软件，但只做加法：不去重、不提示冲突，编码错误也会原样带进结果。请务必保存为 UTF-8，不要存成 ANSI。

## 合并后如何检查并去重

动手前先把原始 VCF 复制到另一个文件夹，合并砸了还能重来。

按姓名排序，重复的人通常挨在一起。电话要先统一写法再比较：`+86 138 0000 0000`、`0086 138 0000 0000` 和 `138 0000 0000` 是同一个号码。加一列 `COUNTIF` 统计电话出现的次数，或者用条件格式把重复值标红，几秒就能看出哪些行撞号。确认是同一个人后，保留字段填得更全的那一行。想先弄清字段和列怎么对应，可以看 [VCF 文件怎么用 Excel 打开](/zh/blog/vcf-wenjian-zenme-dakai/)。

最后数一数：用文本编辑器打开合并后的 VCF，`BEGIN:VCARD` 出现几次就是几条联系人，和表格里剩下的行数对得上，就说明合并成功。

## 常见问题

**会不会丢字段**
姓名、电话、邮箱、公司、地址、备注这些常规字段都有对应的列，来回转换也会保留。照片、生日、某些应用私有的 `X-` 属性可能保不住，所以在核对结果之前不要删原始文件。

**合并后的 VCF 能导回手机吗**
能。它就是一个含多个 `BEGIN:VCARD` 的普通 `.vcf`：iPhone 可以从「文件」App 打开，Android 在通讯录的「管理」→「导入」里选择。

**文件数量有上限吗**
我们没有公布固定的上限。真正的限制来自浏览器内存和文件体积，几万条联系人建议分批处理，预览才不会卡。

**数据会上传吗**
不会。VCF 转表格、表格转 VCF 都在浏览器里完成，文件不会发到服务器。

## 总结

把多个 VCF 合成一个，是两步而不是一键：先汇总成表格并去重，再重新导出 VCF。三种方法里，只有表格能让你在导出前逐行比较和清理。先把所有文件一次性放进 VCF 转 Excel 工具，整理好再交给 Excel 转 VCF。
